# ADR-018: 画像URLの動的生成とキーによる管理

## ステータス

- [x] 承認
- [ ] 保留
- [ ] 却下

## 論点

商品画像などのリソースへの参照をデータベースに保存する際、完全なURL（`https://.../image.jpg`）として保存するか、ストレージ上のキー（`products/image.jpg`）として保存するか。

## 決定事項

データベースには**画像キー（Object Key）のみ**を保存し、アプリケーション層（Repository）で環境設定（Base URL）と結合して完全なURLを生成する。

## 決定理由

1. **環境依存の排除**:
    - 開発環境、ステージング、本番環境でストレージのドメインやパスが異なる場合でも、DBデータを変更することなく環境変数（`R2_PUBLIC_URL`）の切り替えだけで対応できる。
2. **ストレージ移行の容易性**:
    - 将来的にCDNのドメイン変更やストレージプロバイダの変更があった場合、DB内の全レコードをUPDATEする必要がなく、設定変更のみで済む。
3. **データのポータビリティ**:
    - DBのダンプデータを別の環境にインポートした際、リンク切れが発生しない。

## 実装詳細

- **DBスキーマ**: `product_images` テーブルの `image_url` カラムを `image_key` に変更。
- **Repository**: `ProductRepository` 等でデータを取得する際、環境変数から取得したBase URLと `image_key` を結合して、ドメインエンティティの `imageUrl` プロパティにセットする。
- **Entity**: ドメインエンティティは引き続き `imageUrl` プロパティを持ち、アプリケーション内部では完全なURLとして扱う（利便性のため）。

## 影響

- 既存のデータがある場合、マイグレーション時にURLからキーへの変換が必要（今回は初期開発段階のためスキーマ変更のみ）。
- APIレスポンスには引き続き完全なURLが含まれるため、フロントエンドへの影響はない。
